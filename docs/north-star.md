# North Star

## English

### Problem

Traditional enterprise systems treat a good as a passive data object. The
numbers may be available, but understanding and action remain dependent on a
person who must assemble the context.

### Vision

> **Bring every product to life.**

> **商品を「管理されるデータ」から、「自ら状態を理解し、助けを求め、学習する存在」へ変える。**

Goods Garden aims to move goods toward living business entities that can:

- sense relevant conditions;
- understand and express a grounded state;
- identify a need and ask for care;
- receive care and record an action;
- verify an outcome; and
- learn from the result.

This is a product and domain model. It does not claim that an AI system has
real emotion, consciousness or subjective experience.

### Goods Garden and Goods Intelligence

**Goods Garden** is the product world experienced by people. **Goods
Intelligence** is the technical kernel that gives a good capabilities for
sensing, understanding, asking, remembering and learning. The product world is
not the same thing as the technical kernel.

### Fundamental loop

```text
State
  ↓
Need
  ↓
Care
  ↓
Action
  ↓
New State
  ↓
Memory / Learning
```

The loop corresponds to the Intelligence Loop:

```text
Living Model        Intelligence Model

State        →      Observe
Need         →      Investigate
Care Request →      Recommend / Escalate
Care Action  →      Act
New State    →      Verify
Memory       →      Learn
```

### Human relationship

Humans are **Caregivers**, not mere execution devices. The intended
relationship is:

```text
Goods ↔ Caregiver
```

It is not `AI → Human`. A good may sense, analyze, express, recommend and ask
for help. Human authority decides whether any action may be autonomous.

### Fundamental rule

> **AI does not own business authority.**

Authority must be explicitly designed. In particular, a fluent explanation is
never evidence of authority, a need or an outcome.

### First principle

> **Data is sensory input, not the user interface.**

Sales, inventory, waste and weather values are possible sensory inputs. The
human-facing output should be the interpreted and traceable state, concern,
need, request, explanation or learning result rather than uncontextualized
dashboard numbers.

## 中文

### Problem

传统企业系统把商品当作被动数据对象。数字可能存在，但理解和行动仍依赖一个人去拼接上下文。

### Vision

> **Bring every product to life.**

> **将商品从“管理的数据”变成“能够理解自身状态、主动求助，并通过结果学习的存在”。**

Goods Garden 旨在让商品逐步成为 living business entity，能够感知相关条件、理解并表达有依据的状态、
识别需求并请求照料、接受照料并记录行动、验证结果、从结果中学习。这是产品与领域模型，不宣称 AI
拥有真实情感、意识或主观体验。

### Goods Garden 与 Goods Intelligence

**Goods Garden** 是人所体验的产品世界；**Goods Intelligence** 是让商品获得感知、理解、求助、记忆和学习能力的
技术内核。产品世界不等于技术内核。

### Fundamental loop 与 Human relationship

基础循环是 `State → Need → Care → Action → New State → Memory / Learning`。Human 是 **Caregiver**，不是
单纯的执行器，关系是 `Goods ↔ Caregiver`，而不是 `AI → Human`。商品可以感知、分析、表达、推荐和求助，
任何自主行动权限都必须由人类明确设计。

### Fundamental rule 与 First principle

> **AI does not own business authority.**

权限必须显式设计；流畅的解释永远不是权限、需求或结果的证据。

> **Data is sensory input, not the user interface.**

销售、库存、废弃和天气数值是可能的感官输入。面向人的输出应是有上下文且可追溯的状态、担忧、需求、求助、
解释或学习结果，而不是脱离语境的 dashboard 数字。
